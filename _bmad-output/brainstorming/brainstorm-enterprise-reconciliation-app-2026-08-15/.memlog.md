- (technique) started Kill the Crown Jewel — delete the single best feature and redesign to win without it
- (direction) User asked facilitator to use judgment to select the crown jewel
- (question) User requested a summary of the document before continuing the exercise
- (decision) Working platform choice: Electron desktop application
- (technique) started SCAMPER Method — Substitute, Combine, Adapt, Modify, Put-to-other-use, Eliminate, Reverse
- (idea) Keep all proposed workflow dependencies and steps; no substitution
- (direction) User asked facilitator for a view on responsibility substitution
- (decision) User must review every unmatched record; no uncertain-exception-only review
- (technique) SCAMPER lens switched to Combine
- (insight) User has no initial view on workflow steps to combine
- (idea) Avoid failure when reading the attachment
- (idea) Avoid failure to persist user comments
- (idea) Avoid failure to save final output to the shared path
- (decision) Block the reconciliation run if email attachments cannot be read properly
- (direction) User asked facilitator for a view on attachment-read failure feedback
- (decision) Attachment-read failure UI must show the exact email and attachment plus a plain-language reason
- (technique) SCAMPER lens switched to Adapt
- (idea) Preserve existing VBA mapping logic for mapping broker trades to OT/MUREX using ISIN, amounts, quantities, and related fields
- (decision) Faithful migration of VBA mapping logic will be proven by correct reconciliation output
- (decision) Electron reconciliation output must match existing VBA results exactly for every historical test file
- (technique) SCAMPER lens switched to Modify
- (idea) Show reconciliation results in UI grids/tables with all necessary filters
- (idea) User selects an as-of date, then starts reconciliation
- (idea) App retrieves broker data from email and OT/MUREX data from a folder, then applies the reconciliation logic
- (idea) UI displays matched, unmatched, broker-missing, and OT/MUREX-missing records
- (idea) Users can add and save comments on reconciliation records
- (idea) Users select a broker from a dropdown and send an email containing that broker’s relevant output details
- (idea) Save the full reconciliation report to a shared path
- (technique) SCAMPER lens switched to Put-to-other-use
- (insight) User has no initial view of additional uses for reconciliation run results
- (direction) User asked facilitator for a view on a secondary use of reconciliation results
- (insight) User defines unresolved items primarily as reconciliation mismatches requiring action
- (technique) SCAMPER lens switched to Eliminate
- (decision) Do not remove any proposed step, field, or screen at this stage
- (technique) SCAMPER lens switched to Reverse
- (idea) When starting from unresolved items, users check the reason, add comments, and send emails when necessary
- (insight) Core product framing: a trustworthy Electron reconciliation engine with an exception-resolution workspace. Exact parity with existing VBA output creates trust; attachment-read blocking and clear failure feedback protect input integrity; filterable grids, persistent comments, broker follow-up, and shared-report saving turn outputs into a controlled resolution workflow.
